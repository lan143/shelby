# AGENTS.md

Firmware **Shelby** for a home-automation controller on the ESP32 board **Kincony KC868-A2**. Stack: PlatformIO, Arduino framework, ESP32 (`espressif32`), C++ with vendored `ed-*` libraries, LittleFS-hosted Preact SPA web UI, MQTT/Home Assistant. Repository: `git@github.com:lan143/shelby.git`, branch `main`. Read `RTK.md` for the command-output conventions used in this repo.

## Build & deploy

| Task | Command | Notes |
|---|---|---|
| Install frontend deps | `npm --prefix frontend ci` | Or `npm install` when the lockfile is intentionally changing; Node/npm required |
| Build web assets | `npm --prefix frontend run build` | Runs `tsc --noEmit` + Vite and regenerates `data/` |
| Build | `pio run -e kc868a2` | USB target, `board=esp32dev` |
| Flash firmware | `pio run -e kc868a2 -t upload` | USB |
| Flash web assets | `pio run -e kc868a2 -t uploadfs` | LittleFS; run the frontend build first — `data/` is generated output. First install and after any `frontend/` or `data/` change |
| OTA firmware | `pio run -e kc868a2_ota -t upload` | `kc868a2_ota` extends `kc868a2`; espota to `192.168.1.35` with `--auth=<password>` |
| Serial monitor | `pio device monitor` | 115200 baud; build diagnostics via `rtk err` / `rtk summary` (see `RTK.md`) |

Frontend prerequisite: `frontend/package.json` depends on local sibling packages via `file:../../ed-config/frontend` and `file:../../ed-network/frontend`, so the ed-config and ed-network repos must be checked out next to shelby for `npm --prefix frontend install/ci` to resolve.

There are **no tests, no CI, and no linter** beyond `-Wshadow` and the frontend's `tsc --noEmit`. Verification is: compile, build the frontend, flash firmware + filesystem, observe serial output at 115200, and confirm state/commands in the SPA and Home Assistant.

Build flags: `-Wshadow`, `-DCORE_DEBUG_LEVEL=5`, `-DCONFIG_LOG_COLORS=1`. `board_build.filesystem = littlefs`.

## Hardware

| Function | GPIO / setting | Notes |
|---|---|---|
| Gate relay | `RELAY_GATE` = 2 | Native relay, `reverse=false` |
| Door relay | `RELAY_DOOR` = 15 | Native relay, `reverse=false` |
| Gate open end signal | `GATE_OPEN` = 36 | `INPUT`, active low (`digitalRead() == 0`) |
| Gate close end signal | `GATE_CLOSE` = 39 | `INPUT`, active low (`digitalRead() == 0`) |
| RS485 RX | 35 | `Serial2`, `SERIAL_8N1` |
| RS485 TX | 32 | Speed from config, default 9600 |
| Ethernet PHY | LAN8720 | `ETH_ADDR=0`, power pin `-1`, MDC 23, MDIO 18, clock `ETH_CLOCK_GPIO17_OUT` |
| Config EEPROM | 1500 bytes | `EEPROM_SIZE` |

The KC868-A2 has a built-in RJ45 Ethernet port. The board identity is: name `Shelby`, model `KC868-A2`, manufacturer `Kincony`, HW `1.0.0`; the FW version is a git-derived build stamp injected by `scripts/platformio_version.py` (fallback `unknown`), e.g. `v1.2.0-25ee9b3-dirty`.

### RS485 devices

| Device | Default address | Usage |
|---|---|---|
| WB-MR6C | 2 | Relays 1, 4, 5, 6; inputs 0,2,3,4,6 set to frequency mode in `setup()`. Input 1 is owned by the EDCommon binary sensor, which also sets it to frequency mode. |
| QDY-30A | 1 | Holding regs `0x0002` (unit) and `0x0003` (dot position) read once at boot; level reg `0x0004` polled every 60 s |

MR6C channel map: 1 = lawn watering, 4 = decorative light, 5 = parking light, 6 = street light.

## Runtime architecture

`setup()` constructs global objects (constructor dependency injection), loads config from EEPROM (migrating a v2 blob when present; a pending `/config.restore.pending` marker is applied first), mounts LittleFS, initializes network, OTA, MQTT, discovery, gates, MR6C, EDCommon relays, the gates-open binary sensor, both cover command consumers, and QDY-30A. The EDCommon entities own their MQTT/discovery wiring; `main.cpp` only composes them. `handler.init()` is the last setup step: it starts the HTTP server only after every device snapshot source is wired.

`loop()` order is significant: `networkMgr.loop()`, `discoveryMgr.loop()`, `ArduinoOTA.handle()`, `gates->loop()`, `healthCheck.loop()`, `septic->update()`, `networkLogger.update()`, `gatesOpenSensor->update()`, `lawnWateringRelay->update()`, `decorativeRelay->update()`, `parkingRelay->update()`, `streetRelay->update()`, and finally a ≤500 ms-throttled `Devices::updateSnapshot()`. The web task only reads `Devices::snapshot`; relay `isEnabled()` performs synchronous Modbus I/O and must stay on the loopTask. Commands are enqueued through EDCommon setters or `Gates::gatesChange()`/`doorChange()`.

Each successful `persistConfig()` stores EEPROM and refreshes the `/config.bin` export mirror on LittleFS; the mirror is not the source of truth and a mirror write failure does not fail the save.

State flow: there is no aggregate `State` any more. Each EDCommon relay/sensor/binary sensor serializes and publishes its own topic; covers are published by `Gates` directly through `EDMQTT::MQTT::publish(topic, payload, false)` on change at most every 500 ms and republished on every MQTT (re)connect edge. After 2 minutes without motion, `Gates` resyncs stuck cover states from the gate-open limit sensor. The gates open sensor is read by `Gates` via `isActive()`; an invalid reading is treated as closed until the first successful MR6C read.

Command flow: each controllable entity subscribes its own `.../set` topic. `GatesCommandHandler` (one instance per cover) maps plain `open`/`close`/`stop` payloads and dispatches to `Gates::gatesChange()` / `Gates::doorChange()`; cover commands are logged with an accept or reject reason; EDCommon relay consumers map plain `on`/`off`. All command consumers reject retained messages.

Timing: all periodic work is non-blocking and scheduled with `esp_timer_get_time()` in microseconds. Do not add blocking `delay()` to `loop()` or module updates.

Network: Ethernet is started first (`hasEth=true`); after repeated connection failures it falls back to Wi-Fi client mode (if `isAPMode=false`) and then to SoftAP. In AP mode the device serves the UI at `http://192.168.4.1/`. Network connect/disconnect callbacks enable/disable the remote logger and connect/disconnect MQTT.

## Web API contract

The SPA in `frontend/` is the reference client; the firmware handlers live in `src/web/handler.cpp` and the snapshot types in `src/control/devices.h`. Keep both sides in sync when changing paths, keys or value formats. Changes use `application/x-www-form-urlencoded`; successful mutating requests answer HTTP 200 with `{}`. Shelby handler validation failures answer **422** with `{"message":"..."}`; persistence or device-not-ready failures answer **500** with the same shape. The `NetworkApi` routes use `{"error":"..."}` instead, and the ed-config backup page reads `{"message":"..."}`.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/api/devices` | Cached device snapshot (`{sections:[...]}`), refreshed by the loopTask at ≤500 ms |
| `POST` | `/api/devices/set` | Cover command or switch toggle |
| `GET`, `POST` | `/api/settings/modbus` | Modbus speed and the two RS485 addresses |
| `GET`, `POST` | `/api/settings` | Septic tank diameter only (the old credential dump was removed) |
| `GET`, `POST` | `/api/settings/mqtt` | Broker, discovery and topic-prefix settings; GET still returns the MQTT password |
| `GET` | `/api/status` | Wi-Fi state, heap, uptime, last reset reason and git-derived firmware version |
| `POST` | `/api/reboot` | Answer `{}`, then restart the device |
| `GET` | `/healthcheck/healty` | `{healty:true}` — misspelling is intentional |
| `GET` | `/healthcheck/ready` | `{ready,message}`; HTTP 500 while not ready |
| `GET` | `/api/wifi/list` | Live Wi-Fi scan via `EDNetwork::NetworkApi` |
| `GET`, `POST` | `/api/network/settings` | Network settings; POST applies live and persists |
| `GET` | `/api/network/status` | Network mode/connection details |
| `GET`, `POST` | `/api/config/backup` | Backup zip download/upload/restore |
| `GET`, `POST` | `/api/config` | Raw `/config.bin` download/upload/restore |

`GET /api/devices` emits only the arrays each section owns:

| Section `id` | Arrays | Items |
|---|---|---|
| `access` | `covers`, `sensors` | covers `gates`, `door` (`id`, `name`, `state`, `available`); sensor `gates_open` (`unit:"", value:boolean`) |
| `lighting` | `switches` | `watering_the_lawn`, `decorative_light`, `parking_space_light`, `street_light` (`id`, `name`, `enabled`, `available`) |
| `septic` | `sensors` | `septic_tank_filling_level` (`m`), `septic_tank_filling_volume` (`m³`), `septic_tank_average_absorption_speed` (`L/h`), `septic_tank_average_incoming_speed` (`L/h`); numeric `value` |

Cover `state` is one of `closed`, `opening`, `closing`, `open`. Analogue sensors use a number `value`; `gates_open` uses a boolean `value` and an empty `unit`. Unavailable entries still carry the key set, with a safe default.

`POST /api/devices/set` requires `id` and exactly one payload field:

| `id` | Required field | Accepted values |
|---|---|---|
| `gates`, `door` | `command` | `open`, `close`, `stop`; `enabled` is rejected |
| `watering_the_lawn`, `decorative_light`, `parking_space_light`, `street_light` | `enabled` | `on`/`off` (or `true`/`false`); `command` is rejected |

Unknown ids, missing fields, a cover sent `enabled` or a switch sent `command` answer 422; a null control pointer or failed `setState()` answers 500 `device not ready`.

Settings POST bodies must carry every key, even when only one value changed:

| Path | Required keys | Validation |
|---|---|---|
| `/api/settings/modbus` | `modbusSpeed`, `addressMR6C`, `addressQDY30A` | speed ∈ {1200, 2400, 4800, 9600, 19200, 38400, 57600, 115200}; addresses 1..254 |
| `/api/settings` | `septicDiameter` | float ≥ 0 |
| `/api/settings/mqtt` | `host`, `port`, `login`, `password`, `haDiscoveryPrefix`, `mqttIsHADiscovery`, `mqttTopicPrefix` | host 1..63 chars, port integer, login/password ≤31 chars, prefixes 1..63 chars; topic prefix must not start/end with `/` or contain spaces; `mqttIsHADiscovery` is the literal `true`/`false` |

`GET /api/settings/modbus` returns `modbusSpeed`, `addressMR6C`, `addressQDY30A`. `GET /api/settings` returns only `septicDiameter`. `GET /api/settings/mqtt` returns the seven POST keys including the plaintext `password`. `POST /api/settings/modbus` applies a speed change live but addresses only take effect after reboot; post-MQTT and septic-diameter changes also require a reboot.

`GET /api/status` returns `wifiStatus` (`connected`/`disconnected`), `freeHeap`, `uptime` (seconds), `lastResetReason` and `fwVersion` (git-derived build stamp, e.g. `v1.2.0-25ee9b3-dirty` or a short hash; `unknown` without git).

Restore flow: `POST /api/config/backup` and `POST /api/config` write `/config.bin`, create `/config.restore.pending` and reboot. At the next boot `src/main.cpp` validates the file (size, `CURRENT_VERSION`, CRC16) and copies it into EEPROM before `configMgr.load()`; any failure keeps the existing EEPROM config. ESPAsyncWebServer matches plain-URI routes BackwardCompatible (exact match OR prefix + `/`, so `/api/settings` also swallows `/api/settings/mqtt`), and the first registered handler wins; therefore registration order must be: static, healthcheck, NetworkApi, `/api/config/backup`, `/api/config`, `/api/settings/modbus`, `/api/settings/mqtt`, bare `/api/settings`, `/api/devices` GET, `/api/devices/set` POST, `/api/status`, `/api/reboot` — register the `/api/config/backup` route **before** `/api/config` and every `/api/settings/<sub>` route **before** bare `/api/settings`, or the shorter path shadows the longer handler.

## MQTT contract

| Entity | State topic | State payload | Retained |
|---|---|---|---|
| Gates (cover) | `{prefix}/gates/state` | `closed`, `opening`, `closing`, `open` | no |
| Gates door mode (cover) | `{prefix}/door/state` | `closed`, `opening`, `closing`, `open` | no |
| Gates open (binary sensor) | `{prefix}/gates_open/state` | `true`, `false` | yes |
| Watering the lawn (switch) | `{prefix}/watering_the_lawn/state` | `{"enabled":"on"}` / `{"enabled":"off"}` | no |
| Decorative light (switch) | `{prefix}/decorative_light/state` | `{"enabled":"on"}` / `{"enabled":"off"}` | no |

| Septic tank filling level (sensor) | `{prefix}/septic_tank_filling_level/state` | plain number, m | yes |
| Septic tank filling volume (sensor) | `{prefix}/septic_tank_filling_volume/state` | plain number, m³ | yes |
| Septic tank average absorption speed (sensor) | `{prefix}/septic_tank_average_absorption_speed/state` | plain number, L/h | yes |
| Septic tank average incoming speed (sensor) | `{prefix}/septic_tank_average_incoming_speed/state` | plain number, L/h | yes |

The gates-open state is absent until the first valid MR6C reading. Command topics and payloads:

| Entity | Command topic | Payload |
|---|---|---|
| Gates | `{prefix}/gates/set` | `open`, `close`, `stop`; anything else maps to stop |

All command consumers reject retained messages. Cover state is published on change at most every 500 ms, republished on MQTT (re)connect edges and resynced from the gate-open limit after a 2 min motion timeout; EDCommon relays publish state on change and refresh it every 60 s; sensors and the binary sensor publish on change and refresh every 60 s. ## Domain invariants — do not break

- Gate commands are ignored unless the door is `CLOSED`; door commands are ignored unless the gates are `CLOSED`.
- `skipCommand` matrix: `OPEN` only from `CLOSED`; `CLOSE` only from `OPENED`; `STOP` only from `OPENING`/`CLOSING`.
- `STOP` resolves to `OPENED`, not an unknown state.
- Native gate/door relays are momentary pulses: ON, then OFF after 0.2 s (200000 µs).
- End signals are sampled every 1 ms into counters constrained to 0..50; motor movement is detected above 25.
- Motor transitions are evaluated every 0.5 s; opening while both are closed enters `OPENING`, end of opening with `isGatesOpen` enters `OPENED`, closing from `OPENED` enters `CLOSING`, end of motion sets both `CLOSED`.
- The gate-end signals are `GATE_OPEN`/`GATE_CLOSE`; the open sensor is MR6C input 1, now owned by `EDCommon::BinarySensor::WBMR6C` (FREQUENCY mode, `reverse=true`). There is no relay-module init-order dependency any more.
- Lawn watering turns off automatically after 20 minutes (`1200000000` µs) through EDCommon's `Relay::withTimeout()`. Relays 4, 5 and 6 are fire-and-forget.
- QDY-30A is polled every 60 s; readings above 3.5 m are rejected; speeds are only calculated below 2.8 m; speeds use 10-sample ring buffers and reset to 0 after 5 minutes without updates; the sensor is "not ready" after 10 minutes without a valid reading.
- Cover and relay state is non-retained; sensor and binary-sensor state is retained; discovery is retained.
- A config schema change requires bumping `CURRENT_VERSION` in `src/config.h`; v2 EEPROM blobs are migrated in `src/main.cpp`.

## Conventions

- C++ style: 4-space indentation, Allman braces, `_camelCase` private members, `PascalCase` classes, one class per `.h`/`.cpp` pair under `src/<module>/`.
- Logging: `LOGx(tag, msg)` macros from `ed-utils`.
- Dependency wiring lives in `src/main.cpp` only; modules receive collaborators via constructors.
- Adding an HA entity: add it in the owning module's `init()` and give it its own state/command topics (EDCommon `withMQTT`/`withDiscovery`, or `Gates`-style direct publishing); update the MQTT contract above.
- Adding a config field: update `src/config.h`, defaults in `configMgr.setDefault()` (`src/main.cpp`), the relevant `/api/settings*` GET/POST handler, the SPA form under `frontend/src/pages/` plus `frontend/src/api/client.ts`/`types.ts`, and bump `CURRENT_VERSION`.
- Frontend API types and request keys mirror the firmware camelCase contract in `src/web/handler.cpp`; change both sides together. Never edit `data/` directly.
- EDCommon uses millisecond update intervals for sensors/binary sensors (`init()` multiplies by 1000) but microseconds for relay timeouts and scheduling; do not mix the units.
- Never write real WiFi, MQTT or OTA credentials into docs, tests or commits; use placeholders such as `<password>`.

## Gotchas & risks

- The old `src/web/handler.cpp` uppercase `"Handler.h"` include was resolved during the web rewrite; it now uses the lowercase `"handler.h"`. Keep the include case matching the file on case-sensitive filesystems.
- The OTA password is hardcoded twice (`ArduinoOTA::setPassword()` in `src/main.cpp` and `--auth=` in `platformio.ini`). The remote logger host/port/URI are also hardcoded in `src/main.cpp` with a `@todo: move to config`. Never copy the actual secret values into documentation.
- The web API has no authentication and WiFi/MQTT credentials are stored as plaintext in EEPROM. Use only on a trusted, isolated LAN. The default AP has no password (`wifiAPHasPassword=false`). `NetworkApi` no longer exposes Wi-Fi passwords (only `hasWifiPassword`/`hasWifiAPPassword`), but `GET /api/settings/mqtt` still returns the MQTT password and the `/api/config` + backup downloads contain all stored credentials.
- `/healthcheck/healty` is a real typo in the `ed-healthcheck` library, not app code. `/healthcheck/ready` is also exposed.
- `GET /api/wifi/list` is now functional and served live by `EDNetwork::NetworkApi` (synchronous scan); the old `/api/settings` credential dump and `POST /api/settings/wifi` route are gone.
- Flashing the filesystem (`pio run -e kc868a2 -t uploadfs`) erases LittleFS, including the `/config.bin` export mirror: download a backup first if the config must survive.
- Cover HTTP commands execute on the async_tcp task and call `Gates::gatesChange()`/`doorChange()`, the same command profile as the MQTT path; do not perform blocking Modbus I/O from the handler.
- `STOP` sets `OPENED`; do not assume `unknown`.
- Lawn watering auto-off is intentional; do not remove it as a "stuck relay" bug.
- Cover/relay state is non-retained while sensor/binary-sensor state and discovery are retained; do not flip these without checking HA entity availability.
- Do not edit `.pio/` or third-party/vendor assets; do not reformat vendored libraries.

## Never do

- Never commit or document real WiFi/MQTT/OTA secrets.
- Never add blocking `delay()` calls to `loop()` or module update paths.
- Never hand-edit `data/`; it is generated by `npm --prefix frontend run build`.
- Never change MQTT topic slugs, payload formats or the config schema without updating HA templates/discovery, the web UI, docs and `CURRENT_VERSION`.
- Never edit `.pio/` or third-party/vendor assets.
