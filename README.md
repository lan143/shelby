# Shelby

Прошивка домашнего контроллера автоматизации на ESP32 (плата **Kincony KC868-A2**). Управляет въездными воротами и калиткой, освещением и поливом газона, а также отслеживает уровень и объём септика. Интегрируется с Home Assistant через MQTT и авто-обнаружение; настройка выполняется через встроенный веб-интерфейс.

## Возможности

- Управление воротами и калиткой: команды открыть/закрыть/остановить, контроль положения по концевикам, взаимные блокировки.
- Четыре канала WB-MR6C: полив газона, декоративный свет, свет парковки, уличный свет.
- Автоматическое отключение полива газона через 20 минут.
- Мониторинг септика: уровень, объём, средняя скорость впитывания и средняя скорость притока.
- Проводной Ethernet (LAN8720) и Wi-Fi с резервным режимом точки доступа.
- MQTT и автоматическое создание сущностей в Home Assistant.
- Веб-интерфейс: статистика устройства и настройки Wi-Fi, MQTT, Modbus и септика.
- Обновление прошивки по воздуху (ArduinoOTA).
- HTTP-проверки здоровья `/healthcheck/healty` (так в библиотеке) и `/healthcheck/ready`.

## Необходимое оборудование

| Компонент | Назначение |
|---|---|
| Kincony KC868-A2 | Основная плата ESP32 с Ethernet, RS485 и реле |
| WB-MR6C | Модуль реле и входов на шине RS485 |
| QDY-30A | Ультразвуковой датчик уровня на шине RS485 |
| Концевики | Датчики конечных положений ворот |
| Блок питания | Питание платы и модулей по документации производителей |

RS485-устройства подключаются к шине A/B. По умолчанию используются адреса: WB-MR6C — 2, QDY-30A — 1; скорость шины — 9600. Адреса и скорость можно изменить в веб-интерфейсе.

| Подключение | Контакт / GPIO |
|---|---|
| Реле ворот (`RELAY_GATE`) | GPIO 2 |
| Реле калитки (`RELAY_DOOR`) | GPIO 15 |
| Концевик открытия ворот (`GATE_OPEN`) | GPIO 36, активный уровень — низкий (0) |
| Концевик закрытия ворот (`GATE_CLOSE`) | GPIO 39, активный уровень — низкий (0) |
| RS485 RX / TX | GPIO 35 / GPIO 32, `Serial2`, 8N1 |
| Ethernet | Встроенный RJ45, PHY LAN8720; MDC 23, MDIO 18, тактирование GPIO 17 |

## Установка прошивки

Понадобятся Python 3 и PlatformIO Core (или расширение PlatformIO для VS Code).

```bash
git clone git@github.com:lan143/shelby.git
cd shelby
pio run -e kc868a2
pio run -e kc868a2 -t upload
pio run -e kc868a2 -t uploadfs
```

- `pio run -e kc868a2 -t upload` прошивает микроконтроллер по USB.
- `pio run -e kc868a2 -t uploadfs` загружает веб-интерфейс в SPIFFS. Выполните эту команду при первой установке и после любых изменений в `data/`.
- `pio device monitor` открывает монитор последовательного порта на скорости 115200.

## Первый запуск

1. Подключите плату к компьютеру по USB, прошейте прошивку и файловую систему.
2. Если Ethernet и Wi-Fi недоступны, контроллер поднимает точку доступа `Shelby_<MAC>` без пароля.
3. Подключитесь к этой точке доступа и откройте `http://192.168.4.1/`.
4. В разделе **Settings** укажите параметры Wi-Fi и MQTT.
5. Сохранение настроек перезагружает устройство.

После настройки Wi-Fi контроллер подключается к сети как клиент. При подключённом Ethernet-кабеле используется встроенный порт LAN8720. Если сеть снова станет недоступна, устройство вернётся в режим точки доступа.

## Веб-интерфейс

Веб-интерфейс обслуживается на порту 80 и состоит из двух разделов.

**Statistic**

- статус Wi-Fi (`connected` / `disconnected`);
- время работы с момента запуска;
- свободная память кучи;
- причина последней перезагрузки.

Данные обновляются автоматически каждые 10 секунд.

**Settings**

- Wi-Fi: SSID и пароль;
- MQTT: хост, порт, логин, пароль, единый префикс топиков устройства, префикс авто-обнаружения Home Assistant, включение discovery;
- Modbus: скорость (1200–115200) и адреса WB-MR6C и QDY-30A (1–254);
- диаметр септика.

Сохранение любой формы отправляет настройки и затем запрашивает перезагрузку через `/api/reboot`. Ошибки проверки возвращаются в формате JSON с кодом 422.

Сканирования Wi-Fi в интерфейсе нет: эндпоинт `/api/wifi/list` присутствует, но его обработчик не реализован.

## Home Assistant

Для интеграции нужны MQTT-брокер и включённое авто-обнаружение в Home Assistant. По умолчанию используется префикс `homeassistant`; его можно изменить в настройках MQTT.

После публикации discovery-конфигураций в Home Assistant появляются сущности:

| Сущность | Тип | Топик состояния |
|---|---|---|
| Ворота | cover, класс `gate` | `{prefix}/gates/state` |
| Калитка | cover, класс `door` | `{prefix}/door/state` |
| Ворота открыты | binary_sensor, класс `garage_door` | `{prefix}/gates_open/state` |
| Полив газона | switch | `{prefix}/watering_the_lawn/state` |
| Свет парковки | switch | `{prefix}/parking_space_light/state` |
| Уличный свет | switch | `{prefix}/street_light/state` |
| Декоративный свет | switch | `{prefix}/decorative_light/state` |
| Уровень септика | sensor, м | `{prefix}/septic_tank_filling_level/state` |
| Объём септика | sensor, м³ | `{prefix}/septic_tank_filling_volume/state` |
| Средняя скорость впитывания | sensor, л/ч | `{prefix}/septic_tank_average_absorption_speed/state` |
| Средняя скорость притока | sensor, л/ч | `{prefix}/septic_tank_average_incoming_speed/state` |

Объём и скорости септика создаются только при заданном диаметре (`septicDiameter != 0`). Значение бинарного датчика ворот появляется после первого успешного чтения входа MR6C и публикуется retained.

## MQTT API

У каждой сущности свои топики состояния и команд; общий префикс по умолчанию — `shelby/<chipID>`. Префикс задаётся в веб-интерфейсе, порт брокера по умолчанию — 1883. Префикс авто-обнаружения Home Assistant — `homeassistant`.

| Назначение | Топик |
|---|---|
| Префикс топиков устройства | `shelby/<chipID>` (`{prefix}`) |
| Авто-обнаружение HA | `homeassistant` (префикс) |

Состояния:

| Сущность | Топик | Payload |
|---|---|---|
| Ворота | `{prefix}/gates/state` | `closed`, `opening`, `closing`, `open` |
| Калитка | `{prefix}/door/state` | `closed`, `opening`, `closing`, `open` |
| Ворота открыты | `{prefix}/gates_open/state` | `true`, `false` |
| Полив газона | `{prefix}/watering_the_lawn/state` | `{"enabled":"on"}` / `{"enabled":"off"}` |
| Декоративный свет | `{prefix}/decorative_light/state` | `{"enabled":"on"}` / `{"enabled":"off"}` |
| Свет парковки | `{prefix}/parking_space_light/state` | `{"enabled":"on"}` / `{"enabled":"off"}` |
| Уличный свет | `{prefix}/street_light/state` | `{"enabled":"on"}` / `{"enabled":"off"}` |
| Уровень септика | `{prefix}/septic_tank_filling_level/state` | число, м |
| Объём септика | `{prefix}/septic_tank_filling_volume/state` | число, м³ |
| Средняя скорость впитывания | `{prefix}/septic_tank_average_absorption_speed/state` | число, л/ч |
| Средняя скорость притока | `{prefix}/septic_tank_average_incoming_speed/state` | число, л/ч |

Команды:

| Сущность | Топик | Payload |
|---|---|---|
| Ворота | `{prefix}/gates/set` | `open`, `close`, `stop`; любое другое значение — остановка |
| Калитка | `{prefix}/door/set` | `open`, `close`, `stop`; любое другое значение — остановка |
| Полив газона | `{prefix}/watering_the_lawn/set` | `on`, `off` |
| Декоративный свет | `{prefix}/decorative_light/set` | `on`, `off` |
| Свет парковки | `{prefix}/parking_space_light/set` | `on`, `off` |
| Уличный свет | `{prefix}/street_light/set` | `on`, `off` |

Примеры:

```text
Топик:   shelby/<chipID>/gates/set
Payload: open
```

```text
Топик:   shelby/<chipID>/street_light/set
Payload: on
```

```text
Топик:   shelby/<chipID>/street_light/state
Payload: {"enabled":"on"}
```

Состояние ворот и калитки публикуется при изменении не чаще раза в 500 мс; состояние реле — при изменении и повторно каждые 60 секунд; датчики и бинарный датчик — при изменении и повторно каждые 60 секунд.

Состояние ворот, калитки и реле публикуется без флага retained; состояние датчиков и бинарного датчика, а также discovery-конфигурации Home Assistant — с retained. Команды, отправленные с флагом retained, игнорируются.

## Мониторинг септика

Датчик QDY-30A опрашивается по Modbus каждые 60 секунд. При старте считываются служебные регистры единиц измерения и положения десятичной точки, затем читается регистр уровня.

- Уровень пересчитывается в метры и округляется до трёх знаков.
- Показания выше 3,5 м отбрасываются как недостоверные.
- При ошибке чтения или отбраковке следующая попытка выполняется в очередном цикле опроса.
- При заданном диаметре объём считается как `π × (диаметр / 2)² × уровень`, в м³.
- Средняя скорость впитывания считается при падении уровня, средняя скорость притока — при росте; обе — в л/ч и только при уровне ниже 2,8 м.
- Скорости усредняются по кольцевому буферу из 10 значений и сбрасываются в 0, если обновлений не было 5 минут.
- Если корректных показаний нет 10 минут, датчик считается неготовым; это видно через `/healthcheck/ready`.

Диаметр септика задаётся в настройках. Если диаметр равен нулю, уровень продолжает публиковаться, но объём и скорости не рассчитываются.

## Обновление по воздуху (OTA)

OTA выполняется через ArduinoOTA. Перед использованием:

1. Укажите в `platformio.ini` IP-адрес устройства в `upload_port`.
2. Задайте пароль OTA в `platformio.ini` (`--auth=<password>`) и в `src/main.cpp` (`ArduinoOTA.setPassword(...)`); значения должны совпадать.

```bash
pio run -e kc868a2_ota -t upload
```

Веб-ассеты в SPIFFS обновляются отдельной командой `pio run -e kc868a2 -t uploadfs` по USB. Не публикуйте реальный пароль OTA.

## Устранение неполадок

| Проблема | Что проверить |
|---|---|
| Ворота или калитка не двигаются | Взаимная блокировка: ворота работают только при закрытой калитке, калитка — только при закрытых воротах. Проверьте адрес и скорость WB-MR6C, подключение A/B и питание модуля. |
| Нет данных септика | Адрес QDY-30A, скорость шины, подключение A/B. Проверьте `/healthcheck/ready`; после 10 минут без корректных данных датчик неготов. Показания выше 3,5 м отбрасываются. |
| Нет подключения к MQTT | Хост, порт, логин и пароль брокера; доступность брокера из сети устройства; правильность топиков и префикса discovery. |
| Устройство не в сети | Контроллер сам поднимает точку доступа `Shelby_<MAC>`. Подключитесь к ней, откройте `http://192.168.4.1/` и заново сохраните настройки Wi-Fi. |
| Полив прекратился сам | Это штатное поведение: полив отключается через 20 минут. |
| Нужно узнать причину перезагрузки | Раздел **Statistic** в веб-интерфейсе или `GET /api/status`. |
| Ошибка при сохранении настроек | Сервер возвращает JSON с кодом 422 и текстом ошибки; проверьте диапазоны адресов, скорость Modbus и длины полей. |

## Ограничения и безопасность

- Веб-API не имеет аутентификации. Используйте устройство только в доверенной изолированной сети.
- Wi-Fi и MQTT-учётные данные хранятся в EEPROM в открытом виде. Ограничьте физический доступ к плате.
- Точка доступа по умолчанию не защищена паролем (`wifiAPHasPassword=false`). Настраивайте устройство в доверенном месте.
- Пароль OTA захардкожен в прошивке и в `platformio.ini`. Обязательно смените его перед вводом в эксплуатацию и не публикуйте значение.

## Разработка

Архитектура, инварианты, контракт MQTT и правила работы с репозиторием описаны в `AGENTS.md`. Соглашения о сокращении вывода команд — в `RTK.md`.

```bash
pio run -e kc868a2            # сборка
pio run -e kc868a2 -t upload  # прошивка по USB
pio device monitor            # последовательный порт, 115200
```

В проекте нет автоматических тестов и CI; проверка выполняется сборкой, прошивкой и наблюдением за последовательным портом и Home Assistant.
